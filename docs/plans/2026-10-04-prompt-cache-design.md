# prompt-cache: дизайн

Дата: 2026-10-04 · bb 0.45.0 · plugin SDK 0.6.15

## Цель

Плагин показывает, как работает кеш промпта в треде: какая доля промпта пришла из кеша, сколько осталось до истечения кеша и что делать, если кеш истёк на большом контексте. Аналог мода `observability/prompt-cache-control` из claude-code-templates, но для всех провайдеров bb.

Плагин ничего не кеширует. Кешем управляют CLI и API; bb не стоит между ними.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Один плагин или по плагину на CLI | Один | bb нормализует usage всех провайдеров в событие `thread/tokenUsage/updated` |
| Где логика | Во фронтенде (`useSdk`) | Браузерный SDK читает события треда, подписывается на изменения и вызывает `compact`. Бэкенд объявляет только настройки |
| Где UI | Бейдж в шапке треда, всплывающая панель, баннер над composer | Таблица по ходам, таймер в списке тредов и тосты — второй шаг |
| TTL | Настройка на провайдера: `auto` / `5m` / `1h` | Тип аккаунта и env CLI фронтенд не видит |

## Данные провайдеров (сверено на живых тредах)

| Провайдер | `inputTokens` | Кеш | Гранулярность |
|---|---|---|---|
| claude-code | только новые | `cacheReadInputTokens`, `cacheWriteInputTokens` | сумма за ход (из `result`) |
| codex | включает закешированные | `cachedInputTokens` = чтение, запись 0 | запрос |
| pi | только новые | чтение и запись раздельно | запрос |
| acp | — | событий usage нет | — |

Размер промпта последнего запроса даёт `thread/contextWindowUsage/updated.usedTokens`. У claude-code сумма за ход его не заменяет: ход из нескольких запросов даёт 2,7M при окне 1M.

## Модель — `cache-model.ts`

Чистые функции без React.

- `normalizeUsage(providerId, last)` → `{ read, write, fresh, prompt }`. Для `codex` `fresh = input − read − write`, `prompt = input`. Для остальных `fresh = input`, `prompt = input + read + write`.
- `resolveTtl(providerId, setting, rateLimits)`:
  - `5m` / `1h` из настройки;
  - `auto` для claude-code: `kind: "subscription-window"` со статусом `allowed` или `warning` → 1 ч, иначе 5 мин;
  - `auto` для остальных → 5 мин.
- `deriveCache({ providerId, events, rateLimits, ttlSetting })` → снимок или `null`:
  - события старше последнего `thread/compacted` или `thread/context/cleared` не учитываются;
  - нет usage → `null`, и бейдж не рисуется;
  - отчёт usage с нулевым `prompt` пропускается: это ход без запросов к модели, например slash-команда мода cache-watch. bb пишет для него нулевой usage, контекст 0 и снимок после хода; без пропуска бейдж перезапускал отсчёт, хотя кеш не трогали (найдено на живом треде);
  - `lastActivityAt` = самое свежее из usage и contextWindowUsage без `snapshot` (снимок bb делает после хода, а не по запросу) и с ненулевым размером;
  - `contextTokens` = последний ненулевой `usedTokens`, иначе `prompt`.
- `cachePhase(snapshot, now, warnMs)` → `warm` (больше 40% TTL), `cooling`, `expiring` (не больше `warnMs`), `expired`.
- `findRewrites(providerId, events)` → `{ rewrites, latest }`: отчёты, которые отправили прежний контекст заново, а не прочитали его из кеша. Порог: контекст ≥ 20k и не меньше половины контекста.
  - request (Codex, Pi): общий с предыдущим запросом промпт (меньший из двух `prompt`) − `read` текущего;
  - turn (Claude Code): `write` хода − рост контекста за ход. Контекст до хода и после — первый отчёт о контексте с размером после предыдущего и после этого usage. Сумма чтений за ход промах не показывает: остальные запросы хода читают уже записанный кеш;
  - пары не строятся через compaction/clear и от отчёта с нулевым `prompt` (ход `/compact`).
  - Проверено на живом треде: тёплый ход записал 16 928 при росте контекста на 16 601.
- `modelPrice(model)` и `promptCost(price, tokens, ttlMs)` → `{ rewrite, warm }`: прайс Anthropic на октябрь 2026, запись в кеш = 1.25× (5 мин) или 2× (1 ч) цены входа, чтение — своя цена модели; Haiku 5.5 дороже на промптах больше 100k. Таблица cache-watch устарела для Opus 5.5 и Sonnet 5.5, сверено с platform.claude.com/docs/en/about-claude/pricing.

## Frontend — `app.tsx`

- `useThreadCache(threadId)`: `threads.get` (провайдер) и три `threads.events.list` с `order: "desc", limit: "1"`: последний usage, последний отчёт о контексте и последние rate limits. Запросы usage и контекста включают `thread/compacted` и `thread/context/cleared`, результаты сливаются по `seq`. Отдельные запросы нужны, чтобы много отчётов о контексте за долгий ход не вытеснили usage со страницы. Подписка `thread:changed` на тред перечитывает данные на `events-appended` с нашими типами событий или без `eventTypes`, а также на `history-compacted` и `history-rewritten`; переподключение realtime тоже перечитывает. Одновременно идёт не больше одной загрузки и ждёт не больше одной следующей; упавшая загрузка не отменяет ждущую.
- Dismiss баннера хранится в общем на модуль сторе (`useSyncExternalStore`), поэтому прячет баннеры треда во всех composer-ах.
- `useNow(active)`: тик раз в секунду, пока идёт отсчёт.
- Окно перезаписей: последние 21 отчёт usage одним запросом — самый старый нужен только как точка отсчёта для следующего. Смена модели (`client/turn/requested`) тоже перечитывает данные. Цена перезаписи у Haiku 5.5 берёт тариф по размеру всего контекста, а не перезаписанной части. Для Claude Code к каждому — `events.list` с `afterSeq`, `order: "asc"`, `limit: "3"` за первым отчётом о контексте с размером. Результат кешируется в эффекте по `seq` отчёта: найденный не меняется, а для не самого нового отчёта не меняется и «не найден». `history-rewritten` сбрасывает кеш.
- Модель — `data.execution.model` последнего `client/turn/requested`: это событие самого bb, оно есть у любого провайдера.
- `experimental_threadHeaderAction` → `CacheBadge`: `98% · 3:41`, цвет точки по фазе; истёкший кеш красит весь бейдж (`destructive`). По клику открывается `Popover` с TTL, полосой времени, ценой следующего сообщения без кеша и с кешем, разбивкой read / write / new, пометкой о перезаписи в последнем ходе, счётчиком перезаписей за 20 ходов и кнопкой Compact при любом истёкшем кеше.
- `composer.customize({ scopes: ["thread"], banners })` → `CacheBanner`:
  - `expiring` и контекст ≥ 20k: «Cache expires in 0:42…» [Dismiss], с ценой следующего сообщения, если модель есть в прайсе;
  - `expired`, контекст ≥ `compactAtTokens`: «Cache expired…» [Compact] [Dismiss], красный;
  - не показывается, пока тред работает (`view.run.isRunning`);
  - Dismiss действует до следующей активности кеша.
- Compact: `sdk.threads.compact({ threadId })`, ошибка → `toast.error`.

## Backend — `server.ts`

Только `bb.settings.define`: `claudeCodeTtl`, `codexTtl`, `piTtl` (select `auto`/`5m`/`1h`), `warnSeconds` (60), `compactAtTokens` (100 000), `banner` (true).

## Ограничения

- claude-code: строка «Last turn» — сумма за ход. Отсчёт идёт от последнего события usage или контекста, а TTL — от начала последнего запроса, поэтому оставшееся время завышено на длительность этого запроса.
- `auto` для claude-code видит подписку только после события лимитов в этом треде. Настройку `promptCacheTtl` и env CLI (`CLAUDE_CODE_PROMPT_CACHE_TTL` и т. п.) плагин не видит — для них есть настройка.
- Цены — список API; на подписке это мерило лимитов, а не счёт. Перезаписи окна оцениваются по модели последнего хода.
- Поддерживать кеш тёплым плагин не может: в SDK нет запроса к модели мимо чата и нет перехвата отправки. Это умеет мод Claude Code cache-watch (`$.model.fork` из того же процесса), см. ниже.
- Codex: TTL у OpenAI плавающий (5–10 мин простоя, до 1 ч); `auto` берёт нижнюю границу.

## Keepwarm: мод cache-watch

[cache-watch](https://github.com/Barncore/cache-watch) — мод Claude Code (v2.1.287+), форк cache-tax. Держит часы кеша, задерживает холодную отправку на большом контексте и через 55 минут простоя пингует кеш через `$.model.fork`: запрос из того же процесса с тем же префиксом читает кеш и продлевает его на час, ответ в чат не попадает.

Что проверено на этой машине (2026-10-11, Claude Code 2.1.296):

- bb запускает `~/.local/bin/claude` в headless-режиме (`--output-format stream-json`, `--setting-sources=user,project,local`), поэтому пользовательские плагины Claude Code грузятся и в тредах bb.
- По документации хуки модов работают в `claude -p` и Agent SDK, а рисование нет: футера и hold card в bb не будет.
- Команды мода работают headless: `claude -p "/cache-watch guard warn"` ответил текстом за 0 ходов модели, настройка сохранилась между сессиями.
- Установлен с `guard warn`: без интерфейса hold card превращается в `{ drop }` — сообщение отбрасывается, а как bb это покажет, неизвестно.

Эксперимент 2026-10-11, тред на Haiku 5.5 с контекстом 64k:

- `/keepwarm 2h`, набранный в поле ввода bb, доходит до мода: ответил мод, без хода модели. Через `bb thread tell` не доходит: bb добавляет префикс `[bb message from thread:…]`, и текст перестаёт быть командой.
- Мод шлёт свою строку статуса каждую минуту. bb пишет её в тред как `provider/unhandled` (`subtype: "ui_status"`, `plugin: "cache-watch"`).
- **Keepwarm в bb не работает.** bb остановил процесс `claude` простаивающего треда примерно через 33 минуты после последнего хода (последний ход 22:19:53, процесс завершился около 22:52). Пинг был запланирован на 23:00, через 55 минут после последнего запроса. Таймер жил в процессе, поэтому пинг не ушёл. Ход в 23:12 поднял процесс заново (`resuming cold`) и записал 55 182 токена при чтении 12 563.
- Ежеминутные события статуса не продлевают жизнь процесса. Настройки для времени простоя у провайдера claude-code нет.
- Цены мода устарели: перезапись 55k токенов на Haiku 5.5 он оценил в $0.11–0.13, а по прайсу это около $0.01.
- Ход команды мода записывает нулевой usage, контекст 0 и снимок контекста. Из-за этого нашёл и исправил баг плагина: такой ход перезапускал отсчёт.
